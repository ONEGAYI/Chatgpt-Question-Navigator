你是一个资深浏览器扩展工程师。请从 0 构建一个 Chrome/Edge 兼容的 Manifest V3 插件项目，用于增强 ChatGPT 网页长对话导航体验。

项目目标：
构建一个本地优先、隐私友好的 ChatGPT 长对话导航插件。它在 chatgpt.com / chat.openai.com 页面右侧注入一个对话导航侧栏/时间轴，自动采集用户已经滚动经过的消息，建立本地缓存。用户可以通过侧栏查看自己发过的问题摘要，悬停预览，点击跳转。对于超远距离、当前 DOM 中不存在的消息，需要实现渐进式跳转算法，而不是简单调用 scrollIntoView。

核心原则：
1. 只使用 DOM 扫描 + 滚动采集 + 本地缓存方案。
2. 不调用 ChatGPT 内部 API。
3. 不 monkey patch fetch / XHR。
4. 不上传任何聊天内容。
5. 不请求 <all_urls> 权限。
6. 插件所有数据仅保存在浏览器本地。
7. 优先索引 user message，不需要完整索引 assistant message。
8. 兼容 Chrome 和 Microsoft Edge。
9. 目标是自用稳定，而不是商店级复杂功能。

推荐技术栈：
- Manifest V3
- TypeScript
- WXT 或 Vite + web extension
- React 或 Preact
- Shadow DOM 隔离 UI
- MutationObserver 监听 ChatGPT DOM 更新
- IntersectionObserver 判断当前可见消息
- chrome.storage.local 或 IndexedDB 保存本地缓存

如果使用 WXT 更方便，请优先使用 WXT。
项目名可以叫 chatgpt-question-navigator。

插件功能需求：

一、基础注入
1. 只在以下页面启用：
   - https://chatgpt.com/*
   - https://chat.openai.com/*
2. content script 注入后，在页面右侧创建一个 Shadow DOM 容器。
3. 容器内渲染一个窄侧栏，默认宽度约 280px，可折叠。
4. 不应破坏 ChatGPT 页面原有布局、滚动、输入框、快捷键。

二、消息采集
1. 自动扫描当前 DOM 中的 ChatGPT 消息节点。
2. 重点识别用户消息，即用户自己发出的 prompt。
3. 对每条用户消息提取：
   - conversationId
   - localMessageId
   - role: "user"
   - text
   - preview，默认前 80～150 字
   - textHash
   - firstSeenAt
   - lastSeenAt
   - lastKnownScrollTop
   - lastKnownScrollRatio
   - approximateOrder
4. localMessageId 不依赖 ChatGPT 内部 API。可以基于 conversationId + role + textHash + approximateOrder 生成。
5. 需要尽量处理重复问题。重复文本不要简单覆盖，应保留多个实例。
6. 使用 MutationObserver 监听新消息出现、回答生成、重新渲染等情况。
7. 使用节流/防抖，避免频繁扫描导致页面卡顿。
8. 当用户滚动时，持续采集当前可见和附近 DOM 中的用户消息，并更新缓存。

三、conversationId 获取
1. 从当前 URL 中提取 conversationId。
2. 例如 /c/{conversationId}。
3. 如果没有 conversationId，比如新建对话页面，则使用临时 key。
4. URL 变化时，需要重新加载对应会话缓存并刷新侧栏。
5. ChatGPT 是 SPA，不要只依赖初次页面加载；需要监听 history pushState / replaceState / popstate 或定期检测 location.href 变化。

四、本地缓存
1. 将采集到的用户消息按 conversationId 存入 chrome.storage.local 或 IndexedDB。
2. 数据结构大致如下：

interface CachedUserMessage {
  conversationId: string;
  localMessageId: string;
  role: "user";
  text: string;
  preview: string;
  textHash: string;
  firstSeenAt: number;
  lastSeenAt: number;
  lastKnownScrollTop: number;
  lastKnownScrollRatio: number;
  approximateOrder: number;
}

interface ConversationCache {
  conversationId: string;
  updatedAt: number;
  messages: CachedUserMessage[];
}

3. 缓存仅本地保存。
4. 提供基础缓存合并逻辑：
   - 相同 conversationId 下合并。
   - 相同 localMessageId 更新 lastSeenAt / scroll 信息。
   - 新消息追加。
5. 提供简单清理策略：
   - 可保留最近 100 个 conversation。
   - 或提供 clear current conversation cache / clear all cache 方法。

五、导航侧栏 UI
1. 右侧显示用户消息列表或纵向 timeline。
2. 每条用户消息显示：
   - 序号，例如 Q1、Q2、Q3
   - preview 摘要
   - 是否当前 DOM 中可直接跳转
   - 是否仅存在于缓存中
3. 鼠标悬停时显示更完整的问题预览。
4. 点击某条问题时触发跳转。
5. 当前阅读区域附近的用户消息需要高亮。
6. 侧栏应该有：
   - 折叠/展开按钮
   - 搜索框，支持在已缓存用户问题中搜索
   - 当前会话采集数量
   - 一个小的状态提示，例如 “Indexed 18 questions locally”
7. UI 样式要轻量、克制，不遮挡 ChatGPT 正文。
8. 使用 Shadow DOM，避免样式污染。

六、直接跳转
当目标消息当前存在于 DOM 中：
1. 找到对应 DOM 节点。
2. 调用 element.scrollIntoView({ block: "center", behavior: "smooth" })。
3. 对目标消息添加临时高亮，例如 1.5 秒。
4. 更新侧栏当前项状态。

七、渐进式远距离跳转
这是 V2 的关键功能。不要简单依赖 scrollIntoView。目标消息如果当前不在 DOM 中，但存在于本地缓存，需要使用渐进式跳转算法。

基本算法：
1. 用户点击目标 cached message。
2. 先扫描当前 DOM，判断目标是否已挂载。
3. 如果已挂载，直接跳转。
4. 如果未挂载：
   - 读取目标消息的 lastKnownScrollRatio / lastKnownScrollTop。
   - 先尝试 window.scrollTo 到估计位置。
   - 等待 DOM 稳定。
   - 重新扫描 DOM。
   - 如果目标出现，精确 scrollIntoView。
   - 如果目标没有出现，根据当前可见用户消息的 approximateOrder 与目标 approximateOrder 判断方向。
   - 分段滚动，而不是一次性大跳。
   - 每次滚动后等待 DOM 更新，再重新扫描。
   - 最多尝试 N 次，例如 20～40 次。
5. 如果仍然找不到目标：
   - 给出 UI 提示：“Target not mounted yet. Scroll near this area or click again.”
   - 不要死循环。
6. 如果用户在自动跳转期间手动滚动、输入、点击其他目标，需要取消当前跳转任务。
7. 需要实现 jump cancellation token。

伪代码结构：

async function jumpToCachedMessage(target: CachedUserMessage) {
  const token = createJumpToken();

  for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt++) {
    if (token.cancelled) return;

    const direct = findMountedMessageByCacheId(target.localMessageId);
    if (direct) {
      direct.scrollIntoView({ block: "center", behavior: "smooth" });
      highlightMessage(direct);
      return;
    }

    const visibleRange = getVisibleUserMessageRange();
    const direction = decideDirection(target, visibleRange);

    if (attempt === 0 && target.lastKnownScrollRatio != null) {
      scrollToApproximateRatio(target.lastKnownScrollRatio);
    } else {
      scrollOneChunk(direction, attempt);
    }

    await waitForDomSettled();
    await rescanVisibleMessages();
  }

  showJumpFailedToast(target);
}

八、可见范围判断
实现 getVisibleUserMessageRange：
1. 从当前 DOM 中找到所有用户消息。
2. 判断哪些消息在 viewport 附近。
3. 映射到缓存项。
4. 返回当前可见范围中的 min approximateOrder / max approximateOrder。
5. 如果无法判断，退化为根据滚动位置和 lastKnownScrollRatio 判断方向。

九、DOM 识别策略
ChatGPT DOM 可能变化，所以不要把选择器写死到过于具体。
需要实现多层 fallback：
1. 优先寻找带有 data-message-author-role="user" 的元素。
2. 如果不可用，寻找语义结构接近的消息容器。
3. 提取文本时排除按钮、复制控件、编辑控件、隐藏元素。
4. 代码需要集中封装在 domAdapter.ts，方便未来维护。
5. 所有 fragile selector 统一放在一个文件，不要散落各处。

十、性能要求
1. 扫描 DOM 要防抖，例如 300～800ms。
2. 滚动事件要 throttle。
3. 不要在每一帧全量 querySelectorAll 大量节点。
4. 消息文本提取要避免重复处理。
5. 对大型长对话，侧栏渲染列表需要简单虚拟化或至少避免过度 re-render。
6. 不要频繁写 chrome.storage.local；应做批量保存/延迟保存。
